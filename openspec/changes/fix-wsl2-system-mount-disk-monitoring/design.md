# Design

## Context

Мотивация — в [proposal.md](proposal.md); контракт — в [спецификации disk-monitoring](specs/disk-monitoring/spec.md). Дизайн фиксирует точность исключения и порядок фильтрации, от которых зависит сохранение обычных дисков.

`readDisks()` в `src/service/collectors/disks.ts` получает `df -kPl` с fallback на `df -kP`. `parseDf()` сохраняет filesystem, mount и объёмы, но не режим монтирования. Linux-ветка вызывает `linuxDisks()`, который фильтрует строки до двух дедупликаций: по устройству и по показателям объёма. Windows и macOS используют отдельные функции.

На WSL2 подтверждён реальный вывод:

```text
Filesystem     1024-blocks  Used Available Capacity Mounted on
/dev/sdb             98720 98720         0     100% /usr/lib/linux-tools/6.18.54.1-microsoft-standard-WSL2
```

`findmnt` подтвердил `ext4` и `ro`; это диагностическое свидетельство, не новая runtime-зависимость. При здоровом корневом диске текущая реализация создаёт ложное критическое предупреждение. При полном обычном диске сохраняется настоящее предупреждение и добавляется ложное.

```text
df → parseDf → linuxDisks → sampler.disks.items
                              ├─ evaluateWarnings → banner / badge count
                              ├─ fullestDisk → compact status
                              └─ panel → disk list / per-disk level
```

## Goals / Non-Goals

**Goals:** одна классификация mount на входе Linux-отбора; тот же отфильтрованный массив во всех потребителях; сохранение действующих формул и правил дедупликации.

**Non-Goals:** новые источники данных, определение WSL через окружение, чтение mount flags в рабочем цикле, новый контракт `/stats`, дублирующие UI-фильтры, изменение порогов, версии пакета, CI или зависимостей. Публикация/релиз требуют отдельной задачи и разрешения.

## Decisions

### 1. Точное семейство путей в существующем Linux-фильтре

Добавить к `LINUX_HIDDEN_MOUNT` альтернативу, эквивалентную `^/usr/lib/linux-tools/[^/]+-microsoft-standard-WSL2$`. Не создавать отдельный настраиваемый механизм исключений или helper для единственного условия. Непустой сегмент не привязан к цифрам конкретной версии; завершающий якорь не скрывает дочерние пути и дополнительные суффиксы.

Классификация применяется только в Linux-ветке и при любом значении `container`. Отдельное определение WSL не нужно: идентификатором служебного семейства принят сам путь. Исключать все read-only, все заполненные диски, весь `/usr/lib/linux-tools` либо конкретное `/dev/sdb` нельзя: это скроет обычные данные или перестанет работать после обновления окружения.

### 2. Исключение до обеих дедупликаций

Сохранить проверку в начальном цикле `linuxDisks()`, до заполнения `byDevice`. Иначе короткий служебный mount может вытеснить длинный обычный alias по устройству или одинаковым показателям; удаление после дедупликации уже не восстановит потерянный обычный mount.

Не менять существующие ключи дедупликации или предпочтение `/`. Их возможные ограничения не исправляются в этом change.

### 3. Не менять downstream-потребителей

`sampler.ts` передаёт результат коллектора в `disks.items`; `warnings.ts` оценивает только эти элементы. `fullestDisk()` и панель также используют этот массив, а статусный badge считает `stats.warnings.length`. Удаление строки на входе устраняет все ложные признаки без изменений `disks.ts`, sampler, warnings, shared API, panel/status или локализаций.

Альтернатива «только подавить предупреждение» отвергнута: служебный диск останется в панели и максимуме. Ветви Windows/macOS и обработка ошибок коллектора остаются нетронутыми.

### 4. Проверки от входных строк до состояния

В `test/fixtures/linux-wsl2-df.txt` сохранить приведённые реальные header и строку `df`, без UUID, серийных номеров и пользовательских путей. Здоровый корень и полный обычный диск задавать в тестах отдельно. Дополнительную версию ядра обозначить как синтетический параметр, а не как реально снятый вывод.

| Проверка | Место | Ожидаемое доказательство |
| --- | --- | --- |
| Реальный WSL mount и другая версия ядра | `test/parsers.test.ts` | Оба исключены при `container=false/true`; остаются root/device или overlay `/` |
| Обычный диск 100% и близкие несовпадения | `test/parsers.test.ts` | Обычные диски сохранены; проверены другой каталог, произвольное имя, дополнительный суффикс, дочерний путь и пустая часть `<kernel>` |
| Коллизии до дедупликации | `test/parsers.test.ts` | Для одинакового device и отдельно одинаковых figures обычный mount длиннее служебного; он сохраняется при обоих порядках строк |
| Здоровый `/` 40% + WSL 100% | `test/sampler.test.ts` | Через существующий harness и результат `linuxDisks(parseDf(...))`: snapshot содержит только `/`, максимум 40%, warnings пуст, число предупреждений 0 |
| Здоровый `/` + `/data` 100% + WSL 100% | `test/sampler.test.ts` | В snapshot остаются `/` и `/data`, максимум `/data` 100%, единственное предупреждение — `critical` для `/data`, число предупреждений 1 |

Остальные показатели harness должны оставаться ниже порогов. Отрицательные проверки отсутствия WSL сопровождать положительными проверками сохранения обычных дисков; не допускать успешного теста при пустом результате. Для collision-тестов явно проверить предпосылку о большей длине обычного mount.

Отдельный автоматический тест mount flag `ro` не добавлять: вход `DfRow` этого свойства не содержит. Сохранение read-only обеспечивается отсутствием такого критерия в фильтре и положительным случаем обычного полного диска. Не монтировать тестовые диски и не заполнять реальные файловые системы ради проверки. Сам read-only сценарий при отсутствии подходящего обычного тома в окружении отметить как не проверенный на оборудовании.

Сначала добавить тесты, затем выполнить `bun test test/parsers.test.ts test/sampler.test.ts` на старой реализации: случаи WSL и связанного состояния должны падать из-за присутствия служебного тома, а не из-за синтаксиса/окружения. Только после этого менять production-код, запускать те же тесты и немедленно выполнять `bun run build`. Не откатывать и не stash-ить пользовательские изменения для red/green.

### 5. Проверяемая готовность, без расширения окружения

После минимального исправления выполнить `bun run check`, `node scripts/smoke.mjs` и `SMOKE_RUNTIME=bun node scripts/smoke.mjs`. В JSON обоих smoke на WSL проверить отсутствие совпадающего mount в `disks.items` и `warnings`: сам `SMOKE OK` проверяет базовую работоспособность, но не это исключение. Не требовать нулевого общего числа предупреждений на реальном хосте: там могут быть реальные проблемы других ресурсов.

В OpenChamber с обновлённым пакетом перезапустить сервис расширения и проверить список дисков, компактный максимум, баннер и badge: служебного mount нигде нет, прочие предупреждения сохранены. Перезапуск исключает показ прежнего snapshot, диски пересобираются с интервалом 30 секунд. Без доступного UI записать ручную приёмку как непроведённую, не выдавать чистые функции за проверку отображения.

Существующий CI содержит Ubuntu/macOS/Windows, Node/Bun smoke и ограниченный Linux container. Не менять CI; результаты реальных платформ отличать от локальных fixture-тестов. Docker доступен как команда, но доступ к daemon и наличие образов не проверены; загрузка образов и изменение окружения требуют разрешения.

При планировании `node_modules` отсутствует. Ранее typecheck завершился TS2688 для `bun`/`node`; полный check остаётся prerequisite реализации. Если зависимости отсутствуют, сначала получить разрешение на `bun install --frozen-lockfile`; не менять manifest/lockfile и не устанавливать ничего в planning-фазе. `crapper`, `dryer`, `mutator` не найдены в PATH: при реализации использовать доступные проектные варианты либо явно отметить непроведённые проверки без самовольной установки.

## Risks / Trade-offs

- [Обычный том намеренно помещён в точный служебный namespace] → Он также будет исключён; принимается классификация по пути, а не доказательство происхождения. Узкий каталог, суффикс и границы сегмента минимизируют риск.
- [WSL изменит каталог или суффикс] → Исключение перестанет совпадать; не расширять его заранее. Для обновления числовой версии запланирован регрессионный тест.
- [Дедупликация скрывает ошибку теста] → Использовать более длинный обычный mount и оба порядка строк для двух видов коллизий.
- [Устаревший bundle или snapshot] → Пересобрать `dist/`, включить его в diff реализации и перезапустить сервис перед UI-приёмкой.
- [Недоступные зависимости, платформы или UI] → Отмечать отдельными ограничениями проверки; не заявлять, что все проверки прошли.

## Migration Plan

Миграции данных, новые настройки, credentials и внешние сервисы не нужны. Изменение поставляется одним согласованным набором: регрессионные тесты, минимальный Linux-фильтр и сгенерированный `dist/`; публикация не входит в этот план. Откат — вернуть этот набор к предыдущему состоянию и перезапустить сервис; данные пользователей не изменяются.
