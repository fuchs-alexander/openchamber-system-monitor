# Proposal

## Why

Служебный read-only том WSL2 `/usr/lib/linux-tools/6.18.54.1-microsoft-standard-WSL2` попадает в мониторинг как обычный диск с заполненностью 100%. Это создаёт ложное критическое предупреждение, завышает максимальную заполненность и счётчик проблем, хотя свободное место на пользовательских дисках может быть достаточным.

## What Changes

- Исключить из Linux-мониторинга точки монтирования `/usr/lib/linux-tools/<kernel>-microsoft-standard-WSL2`, где `<kernel>` — непустая часть одного сегмента пути, без привязки к версии ядра.
- Выполнять исключение до дедупликации дисков, чтобы служебный mount не вытеснял обычную точку монтирования.
- Использовать единый отфильтрованный список для панели дисков, максимальной заполненности, предупреждений, критического состояния и счётчика проблем.
- Сохранить мониторинг обычных дисков, включая заполненные на 100% и read-only, в рамках существующих правил отбора и дедупликации.
- Добавить регрессионные проверки и при реализации пересобрать `dist/`.

## Capabilities

### New Capabilities

- `disk-monitoring`: правила исключения служебных WSL2 linux-tools mounts и сохранения реальных сигналов заполненности. Это новая запись в пустом каталоге спецификаций, а не новый мониторинг с нуля.

### Modified Capabilities

Нет: `openspec list --specs` не обнаружил существующих спецификаций.

## Impact

- Основное изменение: существующий Linux-фильтр в `src/service/collectors/parse-disks.ts`.
- Тесты: `test/parsers.test.ts`, `test/sampler.test.ts` и новая фикстура реального вывода `df`; сгенерированный пакет `dist/` обновляется только на этапе реализации.
- Публичный контракт `/stats`, пороги, зависимости, системные команды, локализации и настройки не меняются. Отдельные исключения в UI и `warnings.ts` не требуются.
- Ветки Windows/macOS и существующая поддержка Linux/Docker сохраняются. Глобальное исключение read-only или заполненных дисков, несвязанный рефакторинг и выпуск релиза вне области изменения.
- Этот этап создаёт только planning-артефакты существующего change; `.openspec.yaml` и записанная в нём цель сохраняются без изменений.
